# M3 —— 知识隔离（可见性接缝）+ Usher 回应后清洗（桥接期）

> 前置阅读:[../architecture.md](../architecture.md)(两平面 / 依赖方向 / 分层 prompt)、
> [M2.md](M2.md)(storyteller 会话边界播种 / usher 台口分流 / §9 的 §5×§9 污染耦合)。
> 本文把 M3 从 roadmap 的一句"知识隔离"**落成一条可见性接缝**,并用它先解掉 M2.md §9
> 记在案的坑:**用户破坏设定的输入被 usher escalate 后仍永久留在共享历史、被后续 beat 放大成既成事实**。

---

## 0. 一句话

打破 M0/M1/M2 一路沿用的"**共享全知**"——每个 agent 看到**逐字节相同**的世界 + 历史前缀。
M3 让每个 agent 拿**过滤后的视图**:不同角色知道不同的事。核心是历史组装唯一咽喉
`message/prompt/builder.py::build_prompt` 里的**一个 per-message 可见性谓词**。
**清洗**是它的退化情形("对谁都不可见"),**知识隔离**是它的一般情形("只对某子集可见")。

## 1. 核心原语:可见性接缝

今天 `build_prompt` 的历史循环**无条件**遍历 `room.history` 每一条,`msg.render()` 刻意与 agent 无关——
这正是"system+history 前缀对所有 agent 逐字节相同 → 共享同一缓存车道"的根(见 builder 文档串)。
M3 在这唯一咽喉插一个谓词:

```python
# domain/types.py::Message
redacted: bool = False                    # 世界否决/清洗:对谁都不可见(软删除)
visible_to: frozenset[str] | None = None  # None=全体;否则仅这些 agent_id(M3 一般情形)

def is_visible_to(self, agent_id) -> bool:
    if self.redacted: return False
    if self.visible_to is not None and agent_id not in self.visible_to: return False
    return True
```

`build_prompt` 只组装 `[m for m in room.history if m.is_visible_to(agent.id)]`。清洗与隔离**共用这一个谓词**。

## 2. 缓存车道代价(必须正视的取舍)

可见性一旦 per-agent 分叉,"逐字节相同前缀"不再成立。策略:

- **redacted 对谁都不可见** → 各 agent 的可见历史仍逐字节一致(只是**变短**) → **仍共享一条车道**。
  清洗一条**中段**历史会打断该点之后的前缀 → 触发一次缓存失活。可接受:违规是稀有事件。
- **visible_to 子集** → 受众不同的 agent 分裂车道。策略:**可见性相同的 agent 共享一条车道**;
  能进不缓存尾部的隔离内容(如**角色秘密**)就进尾部,避免劈开第 0 层世界书缓存。
- **角色秘密**(本期已落地的骨架)走 `build_tail` 的**不缓存尾部** → **零缓存回归**,是"不同角色
  知道不同的事"最省事的第一落点。

## 3. Usher 回应后清洗(本期桥接的实打实交付)

M2.md §9 记下的坑:用户输入**先落库进历史、后由 usher 判**;一条破坏设定的输入即便被 escalate,
也永久留在共享历史里,后续 beat 的 AI agents 把它当**既成事实**继续建构——代价是"**污染复利**"。

**解法**(与 `user_forced` 边界交接同一条路,不引每拍 canon 守卫):

1. **Usher 分出"违规"轴**(与升级方向正交)。`UsherDecision` 加 `violation`;prompt 让模型在方向词后
   追加 `violate`(抵触已确立世界 canon 时,哪怕语气平静)。**只有 `violation` 才排队清洗**;合法强推
   (advance/probe 无 violate)照常 reseed、被正常 canon 化,**不**清洗。
2. **世界先回应,回应后再清洗**。orchestrator 摄入点把违规输入 id 入队 `_pending_redaction`;
   speak 循环消费 `_forced_end`、reseed 世界抗拒会话时转入 `_redact_after_response`;抗拒会话
   **首次成功回应之后**才 `_do_redact`。**顺序保证**:回应期间违规输入仍在历史里(世界据此有据地抵抗),
   回应后消失 → 精确落在"after the NPC response to it"。
3. **仅上下文软删除**(已与用户确认)。`store.redact_message` 置 `messages.redacted=1`(行留库审计) +
   内存 `room.history` 同步置位。Telegram 消息不动——世界剧情内的抗拒回应即是**可见的纠正**。
4. **回复引用防漏**。`_reply_note` 认 `redacted`:被回复目标已清洗 → 只留 `(回⟦id⟧)`、不渲染内容片段,
   否则隐藏内容会从幸存 NPC 回复的内联引用里回流上下文。

## 4. 落地分期(骨架先行,重特性后接;沿用 M2 分期法)

- **阶段 0｜设计文档**〔✅ 本文〕。
- **阶段 1｜可见性接缝 + Usher 回应后清洗**〔✅ 已落地〕:`Message.redacted`/`is_visible_to`;
  `build_prompt` 按可见性过滤 + 断点重挂最后可见条 + `_reply_note` 认清洗;`store` 加 `redacted` 列
  (走既有 `_migrate` 加列法)+ `redact_message`;`UsherDecision.violation` + parser 认 `violate`;
  orchestrator `_pending_redaction`/`_redact_after_response` + `_do_redact`。测试见
  `test_store` / `test_prompt_builder` / `test_usher` / `test_prompts` / `test_conversation`。
- **阶段 2｜per-agent 世界秘密(缓存安全)**〔✅ 已落地〕:`Agent.secret_knowledge` + `prompts/tail_knowledge.md`
  + `build_tail` 注入(不缓存尾部)+ preset/`examples/room.example.json` schema。
- **阶段 3｜M3 一般情形(隔离的生产化)**〔预留,本期只立接缝不写生产逻辑〕:`Message.visible_to` 谓词已在位,
  待补"谁把消息标成只对子集可见"(私语 / storyteller 播种的知情不对称)+ 车道分裂策略。

## 5. 明确不做(本期预留)

- **storyteller 播种知识不对称**(A 学到 X、B 不知道):属阶段 3 生产逻辑,本期只留接缝。
- **世界书生成 / 跨窗 RAG**:M4。
- **纯 AI 的 canon 漂移**(没有 `user_forced`、usher 管不着):延续 M2.md §9 的搁置——将来三选一
  (每拍连贯性 check / 边界让 storyteller 自纠 / prompt 纪律)。本期不建。

## 6. 清洗的覆盖边界(诚实记录)

清洗只兜住**被 usher escalate 的违规**这一条路径。usher 保守回落(模型异常 / 输出无法解析 → 一律 absorb)
若把**真违规误 absorb**,那条输入不入清洗队列、仍会被后续 beat 放大——这是 M2.md §9 记在案的残余入口,
本期**不动机制**。压低放大系数仍靠 §9(b) 的 agents base-prompt 纪律("对用户单方面设定声明默认存疑")。
即:M3 的清洗把**已识别**的源头斩掉,**误判漏识别**的源头留待后续。

## 7. 验证

- **清洗端到端**(离线 mock):构造"安静的 canon 破坏"→ usher `violation=True` → 世界抗拒会话首次回应后,
  `room.history` 该条 `redacted=True`、`store` 中 `redacted=1`、后续 `build_prompt` 历史不含它、回复引用不漏其内容。
  (`test_conversation::test_violation_input_redacted_after_world_responds`)
- **不清洗对照**:合法 `advance` → escalate 但 `violation=False` → 不清洗、正常留史。
- **缓存不变式**:无清洗的普通会话共享历史前缀仍逐字节稳定;清洗事件后允许该点起缓存失活,仅此一次。
- **知识隔离骨架**:配 `secret_knowledge` 的角色只有其尾部含该秘密、第 0/1 层缓存前缀不受影响;
  `visible_to` 子集把某消息只对受众 agent 可见(`test_prompt_builder`)。
- **两平面不变式**:usher / 清洗全在 message 平面 + runtime 接线,storyteller 仍只出 Intent,暗线 agentic 不进前台消息流。
